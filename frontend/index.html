The problem: most agent frameworks keep state in a process or a database the developer runs. Kill the container, rotate the host, hit a Redis eviction — the agent's history is gone, and there was never any way to prove what it "remembered" was even accurate in the first place. Cortex gives any agent a write/recall API backed by permanent, independently-verifiable storage — so memory outlives infrastructure.

How it works

Four systems, one write.

A single write_memory call fans out to permanent storage, on-chain verification, and a fast index — so recall is quick, but the truth underneath it doesn't depend on Cortex staying online.

01

Content → Arweave

The memory itself is written as a permanent, tagged transaction. No database to lose — anyone can look it up by id, forever.

source of truth
02

Hash → X Layer

A content hash is anchored on-chain. Not the memory itself — just proof it existed, at this time, from this agent.

verification
03

Index → Redis

A fast lookup layer so recall doesn't wait on a blockchain query every time. If it's ever unavailable, recall falls back to Arweave directly.

speed, not truth
04

Recall → verified

Every recall re-checks the on-chain anchor. You don't just get the memory back — you get verified: true.

provable

For coding agents

No SDK. Just ask.

If your coding agent already speaks MCP, it doesn't need special Cortex training — it just needs the tool connected. Here's the same write from the demo above, the way it actually happens: in plain language.

You
Remember that we decided to escalate refund disputes over $500 to a human instead of auto-approving them.
Coding agent
Got it — I'll store that as a decision memory so it persists across sessions.
write_memory({ type: "decision", content: "Escalate refund disputes over $500…" })
You
What did we decide about refund disputes again?
Coding agent
Escalate refund disputes over $500 to a human reviewer instead of auto-approving — verified on-chain, written 3 days ago.
recall_memory("7f3a9c…e04b") → verified: true

Available tools

Everything an agent can call.

Same four tools, two ways to read them.

write_memory
Permanently store a structured memory object for an agent. Anchored on Arweave and verified on X Layer.
"agent_id": string, "type": "event"|"decision"|"outcome"|"preference"|"conversation", "content": string, "visibility": "private"|"public"|"permissioned"
recall_memory
Retrieve a previously written memory by its id, with on-chain verification that it hasn't been tampered with.
"id": string, "cid"?: string // optional IPFS fallback
query_memory
Query an agent's memory history, optionally filtered by type — decisions, outcomes, preferences, and more.
"agent_id": string, "type"?: string, "limit"?: number
get_memory_digest
Generate a compressed summary of an agent's memory over a time range. Raw memories are never deleted — the digest links back to every source.
"agent_id": string, "from"?: string, "to"?: string
